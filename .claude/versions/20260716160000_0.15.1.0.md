# Versão 0.15.1.0 — Abas nomeadas pelo conteúdo + limpeza de formatação

Data: 2026-07-16

Patch pequeno, duas frentes. Na 0.14.1.0 implementei os títulos de aba seguindo à risca a convenção
do `PROJECT.md` ("`tela_atual` se refere ao atual setor da aplicação") e devolvi ao dono a
alternativa de usar o **nome do conteúdo**. Ele aceitou: com várias abas abertas,
`Daron Malakian faz piada… - ChronoFeed` identifica a aba, `Notícia - ChronoFeed` não. Aproveitou-se
a versão para zerar a dívida de formatação do repositório (item 2).

## 1. Abas nomeadas pelo conteúdo

- **`/articles/:id`** → título da notícia (`article.title`) em vez de `titles.article`.
- **`/feeds/:feedId`** → nome do feed em vez de `titles.feeds`.
- **Fallbacks preservados**: enquanto o dado não resolve, ambas as telas caem no nome do setor
  (`Notícia`/`Feeds`). Isso mantém um título estável durante o carregamento (em vez de piscar para o
  fallback estático "ChronoFeed") **e** mantém as chaves `titles.article`/`titles.feeds` em uso — não
  viraram chaves mortas.
- **`/feeds`** (índice) e o resto seguem com nome de setor: não há conteúdo específico para nomear.

### Sem requisição extra

`FeedPage` só tinha o `feedId`. O nome vem de `useFeeds()`, que usa a **mesma queryKey `['feeds']`**
que o `FeedTabs` já carrega — ou seja, cache hit do TanStack Query, sem chamada nova à API. Usei
`useFeeds` e não `useOrderedFeeds` porque a ordenação é irrelevante para um lookup por id.

### Nota de i18n

Nomes de conteúdo vêm da API e **não** são internacionalizados — coerente com a regra do projeto
(notícia é exibida no idioma que a API mandar). Só os nomes de setor passam pelo i18n.

### Documentação

A mudança altera a convenção que o dono escreveu, então o `PROJECT.md` foi atualizado: o nome do
conteúdo tem preferência sobre o do setor quando a tela exibe um conteúdo nomeável, com fallback no
setor. A regra original (`{tela_atual} - ChronoFeed`) continua valendo para as demais telas.

## 2. Limpeza da dívida de formatação

`npm run format:check` **já falhava no `master`** antes desta sessão, em dois arquivos — descoberto
por acaso na 0.15.0.0, quando um `prettier --write` amplo demais reformatou o `NewsCard.tsx` de
carona (revertido na hora, por estar fora do escopo daquela versão). O dono pediu para resolver aqui.

- `src/components/news/NewsCard.tsx`: `anchorOrigin`/`transformOrigin` do menu "⋮" excediam a largura
  e foram quebrados em múltiplas linhas. **Puramente cosmético** — mesmos valores, nenhuma mudança de
  comportamento.
- `.claude/versions/20260709235900_0.12.0.0.md`: duas linhas de continuação de parágrafo com
  indentação sobrando. Cosmético; a renderização do markdown não muda.

`npm run format:check` agora passa no repositório inteiro. **Lição de método**: rodar
`prettier --write` com glob amplo (`src/**/*`) varre arquivos fora do escopo da versão e polui o
diff — restringir aos arquivos tocados, ou tratar a limpeza como item explícito (como aqui).

## Arquivos tocados

- `src/pages/ArticleDetailPage.tsx` — título = manchete; fallback nas saídas de carregando/erro.
- `src/pages/FeedPage.tsx` — título = nome do feed via `useFeeds`.
- `src/components/news/NewsCard.tsx`, `.claude/versions/20260709235900_0.12.0.0.md` — só formatação.
- `.claude/PROJECT.md`, `.claude/ROADMAP.md`, `.claude/memory/ui-layout.md`.

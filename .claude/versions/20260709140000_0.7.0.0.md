# Versão 0.7.0.0 — Dev-login e indicador de não-lido por aba

Data: 2026-07-09

## Contexto de planejamento

O bloco 0.7 do roadmap juntava 4 features (indicador de não-lido, CRUD de feeds, CRUD de
preferências, botão de dev-login). Isso é grande demais para "uma versão por vez" e duas dessas
features (CRUD de feeds e de preferências) estreiam toda a camada de formulários
(`react-hook-form` + `zod`). Na sessão de planejamento decidimos **fatiar em 4 minors**:

- **0.7.0.0** (esta) — dev-login + indicador de não-lido (leves, sem formulário).
- **0.8.0.0** — CRUD de feeds (estreia os formulários).
- **0.9.0.0** — CRUD de usuário/preferências (+ renomear "Configurações" → "Preferências").
- **0.10.0.0** / **0.11.0.0** — testes / Taskfile (desceram de 0.8/0.9).

Também ficou registrado: a reconciliação entre as preferências `theme`/`language` do backend e o
toggle/switcher client-side atual será decidida só na 0.9 (por ora seguem client-side).

## O que foi feito

### A) Botão de dev-login

- `VITE_DEV_LOGIN_ENABLED` (novo) em `.env.example`, `.env.local` e tipado em `vite-env.d.ts`;
  exportado como `DEV_LOGIN_ENABLED: boolean` em `config/env.ts`. Default **off** — o botão nunca
  aparece a menos que a flag esteja explicitamente `'true'`, garantindo que não vaze em produção.
- `AuthService.devLogin()` → `POST /users/dev-login` → `AuthTokens`. Como o `refresh`, é um endpoint
  público que estabelece sessão, então usa uma chamada Axios "crua" (bypass dos interceptors).
- `LoginPage`: botão "Entrar como usuário dev" (ícone `Terminal`, `variant=outlined`,
  `color=secondary`) renderizado só quando a flag está ligada; usa `useMutation` + `useSession().login`,
  com estado de `loading` e uma legenda de erro (`auth.devLoginFailed`).

### B) Indicador de não-lido por aba

- `types/feed.ts`: novo tipo `UnreadCountsResponse = Record<string, number>`.
- `FeedsService.checkForNewArticles()` → `GET /feeds/check-for-new-articles` (objeto plano
  `{ [feedId]: unreadCount }`; feeds sem não-lidas simplesmente ausentes).
- `hooks/useUnreadCounts.ts` (novo): `useQuery` com **`refetchInterval` (60s)** — o jeito idiomático
  de fazer polling no TanStack Query, sem `setInterval`/`useEffect` manual. `refetchIntervalInBackground:
false` pausa quando a aba está oculta; `enabled` só dispara quando o chamador libera (feeds prontos).
- `FeedTabs`: cada `Tab` mostra a contagem como uma **pílula inline** (Box arredondado
  `primary.main`) logo após o nome, com `aria-label` i18n (`feed.unreadCount`, com pluralização por
  `count`, sempre com a contagem exata). Contagens acima de 9 viram **"9+"** (`MAX_UNREAD_DISPLAY`).
  Optou-se por pílula inline em vez do `Badge` flutuante do MUI porque o badge posicionado
  absolutamente transbordava a borda da aba e era cortado pelo scroller (pior com nomes longos/zoom);
  a pílula fica no fluxo, sempre dentro do box da aba.
- Invalidação imediata: `NewsCard` (mutation de marcar como lido) e `ArticleDetailPage` (efeito de
  marcar ao abrir) passaram a invalidar também `['unreadCounts']`, então o badge cai na hora sem
  esperar o próximo poll.

### i18n

- Novas chaves em `en` e `pt`: `auth.signInAsDev`, `auth.devLoginFailed`, `feed.unreadCount`.

## Verificação (backend real, origem `localhost:5173` liberada no CORS)

- `GET /v1/feeds/check-for-new-articles` → 200 `{ "<feed>": 18, "<feed>": 18 }`; badges renderizam
  "Kamelot 18" e "Metallica 18".
- Marcar uma notícia (presente nos 2 feeds) como lida → badges caem para **17/17** na hora, e o
  cabeçalho para "17 novas · 20 totais".
- Dev-login de ponta a ponta: logout → botão "Entrar como usuário dev" → `POST /users/dev-login` →
  redireciona para `/feeds/:id` autenticado, badges carregados.
- Pílula "9+" (17 não lidas): medição de DOM confirma que fica **dentro** do box da aba, sem clipping
  à direita nem no topo, em zoom 100% / 150% / 200%. `aria-label` mantém "17 não lidas".
- `npm run build` (tsc + vite), `npm run lint` e `npm run format` verdes.

### Nota de ambiente (CORS × porta)

O preview rodou em `localhost:5199` (a 5173 estava ocupada pelo dev server do usuário). O backend só
libera CORS para `localhost:5173`, então chamadas a partir de 5199 deram `Failed to fetch`. A
verificação foi feita apontando a aba do preview para o server 5173 (origem liberada), que já servia
este código via HMR. Fica o lembrete: a origem do frontend precisa estar em `CORS_ALLOWED_ORIGINS`.

## Testes

`test_manager` não aplicável — a suíte de testes só entra na 0.10.0.0.

## Como testar

1. `.env.local`: `VITE_DEV_LOGIN_ENABLED=true` e `VITE_API_URL` apontando para a API em
   `ENVIRONMENT=development`. Garanta que a origem do Vite (ex.: `http://localhost:5173`) esteja em
   `CORS_ALLOWED_ORIGINS` no backend.
2. `npm run dev`. Na tela de login, use "Entrar como usuário dev".
3. Observe os badges de não-lido em cada aba de feed. Marque uma notícia como lida (menu "..." do
   card ou abrindo a notícia) e veja o badge decrementar imediatamente.
4. Espere ~60s numa aba visível para ver o refetch automático (ou alterne para uma aba oculta e volte).

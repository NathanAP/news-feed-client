# Versão 0.17.0.0 — Feedback de sucesso (notistack) + palavras-chave recomendadas

Data: 2026-07-17

Minor com duas features independentes, ambas em torno do formulário de feed: estrear a camada de
notificação (toasts de sucesso) e sugerir palavras-chave reais da API enquanto o usuário monta o feed.

## 1. Feedback de sucesso — camada de notificação (notistack)

Antes, uma mutation de escrita apenas fechava o diálogo no sucesso; o usuário ficava sem confirmação.
Agora toda ação de escrita dá um toast de sucesso.

- **Biblioteca:** `notistack` (escolha do dono). `SnackbarProvider` montado no `App.tsx`, **dentro do
  `ThemeProvider`** (para herdar o tema) e por fora do `QueryClientProvider` (os hooks que disparam o
  toast vivem na árvore de queries). Config: `maxSnack={3}`, `autoHideDuration={4000}`,
  âncora inferior-central.
- **Onde disparar (decisão de arquitetura):** o toast sai de **dentro do hook de mutation**
  (`onSuccess`), não da tela. Assim a confirmação vale para **todos os gatilhos** de uma ação de uma
  só vez (ex.: excluir feed dá o mesmo toast venha de onde vier) e não há como esquecer de programar
  num caminho novo. Foi a resposta à pergunta do dono no ROADMAP ("colocar numa parte de formulários
  pra sempre ser programado junto").
- **Cobertura:** criar/editar/excluir feed (`useFeedMutations`) e salvar preferências
  (`usePreferences`). Mensagens em i18n (`feed.toast.{created,updated,deleted}`,
  `preferences.saveSuccess`), PT/EN.
- **Convenção registrada:** nova seção **"Convenções de formulários"** em `rules/conventions.md` +
  seção "Feedback de ações" no `PROJECT.md`: *toda mutation de escrita bem-sucedida dá feedback
  visível, disparado de dentro do hook*. Erros continuam podendo ser inline no formulário (`Alert`).

## 2. Palavras-chave recomendadas (nova rota)

`GET /v1/feeds/keyword-suggestions?keywords=&limit=` → `{ strategy, suggestions: [{ keyword, count }] }`.

- **Serviço/tipos:** `FeedsService.keywordSuggestions(keywords, limit?)` monta a query (keywords em
  CSV, encodadas por `URLSearchParams`). Tipos em `types/feed.ts`: `KeywordSuggestion`,
  `KeywordSuggestions` e `KeywordSuggestionStrategy` (`related`/`popular`) como objeto `as const` +
  união derivada (convenção do projeto, sem `enum` de TS).
- **Hook:** `useKeywordSuggestions(keywords, enabled)` com **debounce de 400 ms** (`useDebouncedValue`,
  novo utilitário genérico). Debouncia o **CSV (primitivo)**, não o array — um array com nova
  identidade a cada render zeraria o timer para sempre. `placeholderData: keepPreviousData` para os
  chips não piscarem entre digitações; `staleTime` de 60 s. Re-consulta conforme as keywords mudam:
  `popular` sem nada escolhido, migrando para `related`.
- **UI:** `KeywordSuggestions` (chips clicáveis) abaixo do `KeywordsInput` no `FeedFormDialog`. Rótulo
  pela `strategy` ("Relacionadas às suas palavras-chave" / "Populares agora"); `count` no tooltip
  ("N notícias"); ícone `+` no chip como affordance. Clicar adiciona a keyword (via `setValue` +
  `normalizeKeywords`, com `shouldValidate` para o erro de mínimo cair na hora). Some quando: diálogo
  fechado, no limite de 20 keywords, ou sem sugestões. Filtro defensivo contra o lag do debounce:
  nunca sugere uma keyword já escolhida.
- **Sem lazy próprio:** entra no chunk (já lazy) do `FeedFormDialog` (47→48 kB, só ao abrir o
  formulário). Não sobre-fragmentar (regra de `performance.md`).
- **Efeito colateral bom:** ataca de lado o problema aberto das **keywords em inglês** (ROADMAP →
  Futuro, item (b)): a pessoa escolhe termos reais em vez de digitar em PT. Não fecha 100% (quem
  ignora os chips e digita à mão ainda erra) — nota atualizada no Futuro.

## Verificação (feita no navegador, via dev-login + backend real na :3000)

- `npm run build`, `lint`, `format:check` — todos verdes; notistack 3.0.2 compila com React 19.
- **Toast:** editar o feed "Metallica" e salvar → capturado no DOM o snackbar **"Feed atualizado."**
  (notistack + i18n PT ok). Create/delete usam o mesmo caminho no mesmo hook.
- **Sugestões:** abrir o diálogo dispara `GET keyword-suggestions`; ao editar um feed com keywords, a
  query saiu com `?keywords=metallica,rock,metal,show,turnê` (CSV + encoding corretos). Sem erros de
  console. O corpus de seed retornou `suggestions: []` no momento (fallback `related`→`popular`
  vazio), então os chips não apareceram visualmente — condição dos dados, não do client; o componente
  corretamente renderiza `null` quando vazio.

## Como testar

1. Login (dev-login em desenvolvimento).
2. **Toast criar:** "Criar feed" → nome + 5+ keywords → Criar → toast "Feed criado." e diálogo fecha.
3. **Toast editar:** menu "⋮" do feed → Editar → mudar o nome → Salvar → toast "Feed atualizado.".
4. **Toast excluir:** menu "⋮" → Excluir → confirmar → toast "Feed excluído.".
5. **Toast preferências:** menu do avatar → Preferências → mudar algo → Salvar → toast "Preferências
   salvas.".
6. **Sugestões:** abrir Criar/Editar feed; com um corpus que tenha keywords populares, chips aparecem
   abaixo do campo. Digitar/adicionar keywords muda o rótulo para "Relacionadas às suas palavras-chave"
   e a lista. Clicar num chip adiciona a keyword. Ao chegar em 20 keywords, os chips somem.

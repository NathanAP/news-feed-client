# Versão 0.10.0.0 — Otimização de bundle (code splitting)

Data: 2026-07-09

## Motivação

Desde a 0.8, o build gerava **um único chunk** (~935 kB / 295 kB gzip) e o Vite emitia o aviso de
`chunkSizeWarning`. Causa: o router importava todas as páginas estaticamente e o _form stack_
(`react-hook-form` + `zod`) entrava junto com a casca. A forma correta de resolver em React + Vite é
**`import()` dinâmico** via `React.lazy` + `Suspense` (rota) e componentes lazy (diálogos pesados).

## O que foi feito

### Ponto 1 — Code splitting por rota

- `routes/lazyPages.ts` (novo): os 6 componentes de página via `lazy(() => import(...).then(m => ({
default: m.X })))` (named exports). Extraído para módulo próprio por causa da regra ESLint
  `react-refresh/only-export-components`.
- `routes/router.tsx`: passou a importar as páginas de `lazyPages`; layouts e guardas seguem eager.
- `components/PageLoader.tsx` (novo): fallback centrado (spinner) das rotas lazy.
- `Suspense` boundaries: em `AppLayout` (ao redor do `Outlet`, para o header ficar estável enquanto o
  chunk da página carrega) e em `RootLayout` (cobre rotas fora do AppLayout: login, callback, 404).

### Ponto 2 — Diálogos de formulário lazy

- `components/feeds/LazyFeedFormDialog.tsx` e `components/user/LazyPreferencesDialog.tsx` (novos):
  embrulham `FeedFormDialog`/`PreferencesDialog` com `React.lazy` + `Suspense` e só renderizam quando
  `open` — assim o chunk do form (RHF + zod) só baixa ao abrir o diálogo. `FeedFormDialog` passou a
  exportar `FeedFormDialogProps`.
- Call sites trocados para os wrappers: `FeedTabs` e `HomePage` (criar), `FeedActionsMenu` (editar),
  `UserMenu` (preferências). `ProfileDialog` seguiu eager (é leve, sem RHF).
- Trade-off aceito: como o wrapper renderiza `null` enquanto fechado, a transição de **fade-out** ao
  fechar é pulada (o `React.lazy` cacheia o módulo, então reabrir continua instantâneo).

## Resultado (build de produção)

- Chunk principal: **935 kB → 488 kB** (gzip **295 kB → 153 kB**). **Aviso de chunk do Vite sumiu**
  (nenhum chunk > 500 kB).
- Chunks separados sob demanda: cada página; `ArticleDetailPage` (~28 kB, leva o **DOMPurify**);
  `FeedFormDialog` (~36 kB) e `PreferencesDialog` (~11 kB) com o form stack; `Alert` (~142 kB, só
  puxado pelos diálogos) deixou de entrar no caminho inicial.
- O `MUI` core permanece no chunk base (usado na casca inteira) — por isso o inicial não cai pela
  metade em bytes absolutos, mas o payload inicial (gzip) caiu ~48%.

## Convenção documentada

- `rules/performance.md` (novo): regras de code splitting (rota como fronteira primária; componentes
  pesados/condicionais como refino; não sobre-fragmentar; sempre `Suspense`; padrão de named export +
  `lazy`) e uma seção de requisições.

## Testes

`test_manager` não aplicável — a suíte de testes entra em versão futura (ver ROADMAP).

## Como testar

`npm run build` e observe os vários chunks (nenhum aviso de tamanho). Em `npm run dev`, navegue entre
feed → notícia (chunk do detalhe carrega) e abra os diálogos de criar feed / preferências (chunk do
form carrega ao abrir). Tudo deve funcionar sem travar.

# Versão 0.3.0.0 — Comunicação com a API + autenticação

Data: 2026-07-07

## Objetivo

Fatia vertical: router escalável, camada de API (Axios em classes) e o fluxo completo de
autenticação com Google, chegando a uma tela com os dados do usuário logado. UI ainda crua
(MUI e i18n vêm na 0.4).

## Feito em duas etapas

### Etapa 1 — Router, sessão e captura de tokens

- **Router** (`src/routes/`): `createBrowserRouter` (data router), paths centralizados em
  `paths.ts` (objeto `as const`), guardas `ProtectedRoute`/`PublicRoute`, `RootLayout` e páginas.
- **Sessão** (`src/contexts/` + `src/hooks/useSession.ts`): `access_token` em memória, `refresh_token`
  no `localStorage`.
- **Fluxo do Google**: `LoginPage` (botão cru → redirect), `AuthCallbackPage` (lê o `#fragment`,
  guarda tokens, limpa a URL, navega), tela de erro (`?error=`), `NotFoundPage`.

### Etapa 2 — Camada de API em classes + sessão real

- **`ApiClient`** (classe base): instância única do Axios + interceptors — injeta `Bearer`,
  refresh no 401 com _single-flight_ e retry, 503 → tela de manutenção. Recebe callbacks da
  sessão via `setAuthHandlers` (evita dependência circular com o React).
- **`AuthService`** / **`UsersService`** (classes): login-url do Google, `refresh` (Axios "cru"
  para não cair no loop do interceptor), `logout`; `getMe()` com mapeamento snake_case → camelCase.
- **`SessionProvider`**: reidratação real no boot via `/auth/refresh`, splash enquanto inicializa,
  registro dos handlers no `ApiClient`, `logout` best-effort + limpeza do cache do Query.
- **`HomePage`**: dados do usuário via TanStack Query (`useCurrentUser`). Avatar com
  `referrerPolicy="no-referrer"` + fallback `onError` (corrige 429 do CDN do Google).
- **React Query Devtools** ligado só em `import.meta.env.DEV`.

## Decisões e aprendizados

- **Classes na camada de dados** (ApiClient/serviços), UI declarativa — conforme convenção.
- **Enums**: `erasableSyntaxOnly` proíbe `enum` do TS; padrão adotado = objeto `as const` + união
  (registrado nas convenções).
- **`react-hooks` v7** proíbe `setState` síncrono em `useEffect` (`set-state-in-effect`). Ajustes:
  parse do callback no inicializador do `useState`; boot com IIFE async (setState só após `await`).
- Pequena duplicação da lógica de refresh (interceptor vs boot) — feita para satisfazer a regra
  acima sem `setState` síncrono; aceitável.

## Dependências adicionadas

`react-router-dom`, `@tanstack/react-query`, `axios`, `@tanstack/react-query-devtools` (dev).

## Verificação

- Build, lint e format verdes.
- Runtime (sem backend): boot sem token → `/login`; 404; callback com `?error=`; callback com tokens
  no fragment → Home + logout — todos verificados no navegador.
- **Fluxo autenticado real**: confirmado pelo usuário contra o backend de pé — login com a conta
  Google funciona, Home mostra nome/email, e o avatar carrega após o fix do 429.

## Pré-requisitos de backend (dev)

`OAUTH_ALLOWED_REDIRECT_URIS` com `http://localhost:5173/auth/callback`; `CORS_ALLOWED_ORIGINS` com
`http://localhost:5173`; backend em `http://localhost:3000/v1`; `ENVIRONMENT=development`.

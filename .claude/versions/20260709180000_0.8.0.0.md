# Versão 0.8.0.0 — CRUD de feeds + modo host do Vite

Data: 2026-07-09

## Objetivo

Ligar o gerenciamento completo de feeds (criar/editar/excluir) — que estreia a camada de
formulários do app — e expor o dev server no IP local.

## O que foi feito

### Modo host do Vite

- `server: { host: true }` no `vite.config.ts`. Comentário no arquivo lembra as dependências de
  backend: a origem LAN (`http://<ip>:5173`) precisa estar em `CORS_ALLOWED_ORIGINS`, e o login
  Google exige o callback `http://<ip>:5173/auth/callback` em `OAUTH_ALLOWED_REDIRECT_URIS`
  (o dev-login não depende do callback).

### Camada de formulários (estreia)

- Instalados `react-hook-form@7`, `zod@4` e `@hookform/resolvers@5`. Padrão adotado: `useForm` +
  `zodResolver`, com o schema recriado por idioma (`useMemo` em `i18n.language`) para mensagens de
  validação localizadas; campos customizados via `Controller`.

### Tipos, serviço e hooks

- `types/feed.ts`: `Feed` ganhou `keywords: string[]`; novo `FeedInput` (`{ name, keywords }`).
- `ApiClient`: novo método `delete<T>`.
- `FeedsService`: `create(input)`, `update(id, input)`, `remove(id)`; `toFeed` passou a mapear
  `keywords` (o `FeedResponse` já os trazia), pré-populando a edição sem requisição extra.
- `hooks/useFeedMutations.ts`: `useCreateFeed`/`useUpdateFeed`/`useDeleteFeed`, todos invalidando
  `['feeds']` e `['unreadCounts']` no sucesso.

### Componentes

- `components/feeds/keywords.ts`: `MIN_KEYWORDS` (5), `MAX_KEYWORDS` (20) e `normalizeKeywords`
  (trim + lowercase + dedupe + cap em 20). Ficou em módulo separado do componente por causa da
  regra `react-refresh/only-export-components` do ESLint.
- `components/feeds/KeywordsInput.tsx`: chips input reutilizável sobre `Autocomplete`
  (`multiple`/`freeSolo`) — digitar + Enter adiciona, ícone do chip remove; contador `x/20` no
  helper text.
- `components/feeds/FeedFormDialog.tsx`: diálogo criar/editar. Valida `name` (≤120) e `keywords`
  (5..20) com Zod; trata erro 409 (limite de feeds) com mensagem específica e outros erros com
  mensagem genérica (via `Alert`). Reset no abrir (pré-preenche em modo edição).
- `components/ConfirmDialog.tsx`: diálogo de confirmação reutilizável (usado para a exclusão, que é
  permanente e sem reativação).
- `components/feeds/FeedActionsMenu.tsx`: menu "⋮" (Editar/Excluir) do **feed ativo**, renderizado no
  cabeçalho da lista. Resolve o feed via `useFeeds()` pelo `feedId`; embute o `FeedFormDialog`
  (edição) e o `ConfirmDialog` (exclusão) e faz a navegação pós-exclusão.

### Fluxos (FeedTabs / NewsList / HomePage)

- `FeedTabs`: "+" abre o `FeedFormDialog` em modo criar — **desabilitado com tooltip quando já há 5
  feeds** (`MAX_ACTIVE_FEEDS`), além do 409 como rede de segurança. As abas ficam **limpas** (só nome
  + pílula de não-lidas). Ao criar → navega para o feed novo.
- `NewsList`: o cabeçalho virou uma linha flex — "X novas · Y totais" à esquerda e o `FeedActionsMenu`
  ("⋮") à direita. **Decisão de UX (a pedido):** editar/excluir saíram das abas e passaram a agir
  sobre o feed **aberto** — assim o gatilho é um `IconButton` normal (não um `<span role="button">`
  aninhado no `<button>` do `Tab`, que era o incômodo da primeira tentativa). Ao excluir o feed ativo
  → navega para o primeiro restante ou estado vazio.
- `HomePage`: o estado vazio (0 feeds) ganhou botão "Criar feed" abrindo o mesmo diálogo.

### i18n

- Novo namespace de chaves `common` (`cancel`/`confirm`/`save`), `feed.*`
  (`manage`/`edit`/`delete`/`limitReached`/`deleteConfirm.*`) e `feedForm.*` (labels, contador,
  placeholder, submit e `errors.*`), em EN e PT.

## Verificação (backend real, dev-login, origem `localhost:5173`)

Round-trip completo, criando feeds de teste e **removendo todos ao final** (feeds reais Kamelot/
Metallica intactos):

- **Estrutura**: abas **sem** gatilho de gerenciar; o "⋮" é um `<button>` no cabeçalho da lista,
  oposto ao "X novas · Y totais", e aponta para o feed ativo (aria-label "Gerenciar feed <ativo>").
- **Criar**: nome + 5 keywords (chips), submit → 201, diálogo fecha, navega para o feed novo, aba
  aparece.
- **Editar**: "⋮" do cabeçalho → Editar abre pré-preenchido (nome + 5 chips); renomear + salvar →
  aba e o próprio botão do cabeçalho atualizam.
- **Validação**: submit vazio → "Informe um nome para o feed." + "Adicione pelo menos 5
  palavras-chave.", diálogo permanece aberto.
- **Limite**: com 5 feeds o "+" fica **desabilitado**; após excluir, reabilita.
- **Excluir**: "⋮" do cabeçalho → Excluir → confirmação ("… será excluído permanentemente. Isso não
  pode ser desfeito.") → remove e navega para outro feed (o cabeçalho passa a apontar para o novo
  ativo).
- `npm run build`, `npm run lint`, `npm run format` verdes. Sem erros de console.

### Nota de ambiente / limitações da verificação

- Mesma pegadinha de CORS/porta: verificação feita apontando a aba para o server `5173` (origem
  liberada). O preview do harness segue instável em navegações cross-origin (reset para `/` /
  viewport 0). O disparo de dialog pelo "+" só abriu via `preview_click` (clique nativo em `.click()`
  dentro de `eval` não abriu); keywords foram adicionadas via eventos sintéticos de teclado.
- **Bundle** subiu para ~922 kB (form libs + `Autocomplete`); o aviso de `chunkSizeWarning` do Vite
  passou a aparecer. Candidato a code-splitting no futuro (não bloqueante).

## Testes

`test_manager` não aplicável — a suíte de testes entra em versão futura (ver ROADMAP).

## Como testar

1. Logue (dev-login) numa origem liberada no CORS do backend.
2. Clique no "+" das abas (ou no botão do estado vazio) → preencha nome e ao menos 5 palavras-chave
   (Enter adiciona cada uma) → Criar.
3. No "⋮" de uma aba, use Editar (pré-preenchido) e Excluir (confirmação).
4. Crie feeds até 5 para ver o "+" desabilitar; exclua para reabilitar.
5. Opcional (host): rode `npm run dev` e acesse por `http://<ip-da-máquina>:5173` de outro
   dispositivo — lembrando de liberar essa origem no CORS e o callback no OAuth do backend.

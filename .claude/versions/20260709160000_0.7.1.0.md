# Versão 0.7.1.0 — Bugfix: transbordo com textos longos

Data: 2026-07-09

## Motivação

Durante a revisão da 0.7.0.0, ao perguntar "e se o nome do feed, o título ou o corpo forem muito
grandes?", testamos com strings patológicas (uma palavra de 144 caracteres **sem espaços**, tipo uma
URL longa) injetadas no app real e medimos o transbordo. Achados:

- **Tela de detalhe (`ArticleDetailPage`)**: o título `h5` não tinha clamp, `word-break` nem
  `overflow: hidden` — um token longo sem espaços gerava **scroll horizontal da página inteira**
  (`scrollWidth 2293` vs `clientWidth 941`). Bug **pré-existente** (desde a 0.5).
- **Card da lista**: título/corpo já eram clampados em 2 linhas e o `Card` tem `overflow: hidden`, mas
  um token longo era **cortado no meio do caractere** (sem reticências), pois `line-clamp` limita
  linhas e não quebra palavras.
- **Nome de fonte** longo no rodapé do card podia espremer a data.
- **Nome de feed** longo deixava a aba muito larga (sem truncagem).

Patch (`0.7.0.0` → `0.7.1.0`), correções aceitas em conjunto.

## O que foi feito (só CSS/sx, sem mudança de lógica)

- **`NewsCard`**:
    - `clamp2` ganhou `overflowWrap: 'anywhere'` → tokens longos quebram e clampam com reticências em
      vez de serem cortados no meio.
    - Título (`subtitle1`) ganhou `minWidth: 0` (item flex) para poder encolher/quebrar.
    - Rodapé: ícone e data com `flex: 'none'`; nome da fonte com `noWrap` + `minWidth: 0` (elipse,
      não empurra a data).
- **`ArticleDetailPage`** (a correção crítica):
    - Título `h5` com `overflowWrap: 'anywhere'`.
    - Box do conteúdo HTML com `overflowWrap: 'anywhere'`, `& pre, & code { white-space: pre-wrap;
overflow-wrap: anywhere }`, `& pre { overflow-x: auto }` e `& img { height: auto }`.
- **`FeedTabs`**: o nome do feed agora vai num `<span>` interno com `overflow: hidden` +
  `text-overflow: ellipsis` + `white-space: nowrap`, e o container do label tem `maxWidth: 200` — a
  contagem "9+" continua sempre visível ao lado.

## Verificação (backend real, origem `localhost:5173`, viewport 941px)

- **Lista**: token de 144 chars no título + nome de feed longo + fonte longa → **sem scroll
  horizontal**; título clampa em **2 linhas**; nome do feed trunca com **reticências** (176px); fonte
  com elipse.
- **Detalhe**: token de 144 chars no `h5` → **sem scroll horizontal** (`pageHorizScroll` de `true`
  para `false`; `h5.scrollWidth == clientWidth`, quebra dentro do box; `overflow-wrap: anywhere`
  computado). O Box do conteúdo HTML também tem `overflow-wrap: anywhere` aplicado.
- `npm run build` (tsc + vite), `npm run lint` e `npm run format` verdes.

### Nota de ambiente

Mesma pegadinha de CORS/porta da 0.7.0.0 (verificar apontando a aba para o server `5173`, a origem
liberada). O preview do harness apresentou instabilidade (viewport colapsando para 0 / voltando a `/`
após navegações cross-origin) — quando isso ocorre a medição de `clientWidth` vem 0 e falseia o teste;
as medições válidas foram feitas com `clientWidth === 941` confirmado antes de medir.

## Testes

`test_manager` não aplicável — a suíte de testes só entra em versão futura (ver ROADMAP).

## Como testar

Abra uma notícia cujo título/corpo tenham uma URL longa (ou force via devtools um texto longo sem
espaços): a página não deve ganhar rolagem horizontal. Na lista, títulos ficam em 2 linhas e nomes de
feed muito longos truncam com reticências na aba, mantendo o "9+".

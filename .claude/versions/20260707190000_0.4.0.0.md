# Versão 0.4.0.0 — Casca do app: Material UI, tema e i18n (placeholder)

Data: 2026-07-07

## Objetivo

Materializar a casca visual do app (referência: Threads) com Material UI, tema dark/light e
internacionalização — tudo com **dados de exemplo (placeholder)**. Sem comunicação com a API
(isso é a 0.5).

## O que foi feito

### Material UI + tema

- `theme/theme.ts`: `createTheme` com `cssVariables` + `colorSchemes` (light/dark). **Dark-first em
  grafite azulado** (`background.default` `#14161b`, `paper` `#1b1e25`, primary `#6b9bff`).
- `App.tsx`: `ThemeProvider` (`defaultMode="dark"`) + `CssBaseline`. Splash (`CircularProgress`) e
  tela de manutenção agora em MUI.
- `index.css`: fundo dark no `body` para evitar flash antes do CssBaseline.

### Internacionalização (react-i18next)

- `i18n/index.ts`: init com `LanguageDetector` (localStorage + navigator), namespaces, `en`/`pt`.
- `i18n/locales/{en,pt}/common.json`: textos da UI.
- Todas as páginas e componentes de chrome usam `t(...)`. `resolveJsonModule` habilitado no tsconfig.

### Casca (layout)

- `components/layout/`: `AppLayout` (header + coluna central `Container maxWidth="sm"`),
  `AppHeader` (`AppBar` transparente + blur; marca, `FeedTabs`, `ThemeToggle`, `UserMenu`),
  `FeedTabs` (abas placeholder + botão "+"), `ThemeToggle` (`useColorScheme`),
  `UserMenu` (avatar + menu: perfil, configurações, **switcher de idioma PT/EN**, sair).
- `components/news/`: `NewsCard` (título + tempo relativo, corpo, rodapé data + fonte; **título e
  corpo com clamp de 2 linhas**; ponto de não-lido) e `NewsList`.
- `data/placeholderNews.ts`: feeds e notícias de exemplo. `types/news.ts`: view-model `NewsCardItem`.
- Rotas: `HomePage` agora renderiza o feed; área autenticada passa por `AppLayout`.

### Switcher de idioma (adicionado a pedido)

- No menu do avatar, seção "Idioma" com Português/English (client-side, `i18n.changeLanguage`,
  persiste no localStorage, muda a UI na hora). **Distinto** da preferência `language` do backend
  (6 idiomas, para tradução de conteúdo) — sincronizar as duas fica para 0.5+.

## Verificação (fluxo real via `dev-login`)

Testado contra o backend real (tokens reais sem Google, via `POST /users/dev-login`):

- Login → casca renderiza com dados reais: header, abas, avatar (foto real, **sem 429**), cards.
- Tema dark grafite confirmado (`body` `#14161b`, card `#1b1e25`); toggle dark↔light **persiste**.
- i18n: PT detectado; switcher PT→EN troca toda a UI na hora e persiste.
- Clamp de 2 linhas no card (corpo com "…").
- Menu do avatar (perfil/config/idioma/sair). Logout → **204**.
- Interceptor real (Bearer → 401 → refresh) e CORS (preflight 204) validados.
- Build, lint e format verdes.

## Bugs encontrados e corrigidos na verificação

1. **Boot vs callback (corrida):** o boot da sessão reidratava o token logo após o login pelo
   callback. Agora só reidrata quando já havia sessão no carregamento (`initialStatusRef`).
2. **Logout dava 401:** o `clearSession()` zerava o `access_token` antes do interceptor (assíncrono)
   do Axios lê-lo → `POST /auth/logout` sem `Bearer`. Corrigido: dispara o logout e limpa a sessão
   no `.finally`. Confirmado **204**.
